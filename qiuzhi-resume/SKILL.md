# 简历编写

按目标岗位画像组织简历内容，AI 实践优先，全栈经历详细，措辞谦逊。

## 输入

- 个人素材：工作经验.md、个人特长.md、职业方向.md（无则主动采集）
- 候选人的硬约束（措辞谦逊、城市发展说明、AI 实践优先）从 qiuzhi-flow 继承

## 处理流程

### 1. 按市场行情定位目标岗位画像

当前行情重点：目标岗位为 **AI 工程类**（AI 应用开发 / AI 工具链 / Agent 工程），以技术能力为主线。AI 相关实践必须重点介绍。

### 2. 素材采集（主动向用户追问，写清楚再进简历）

- **AI 实践**：项目/工具/解决什么问题/技术栈/量化效果。必须问清楚：
  - vibe coding 经历（用过哪些 AI 工具、完成过哪些任务、效率提升多少、是否独立从零开发）
  - 用 AI 解决过的具体问题（按"问题 → AI 方案 → 结果"组织，**尽量带量化数据**）
  - 完成的 AI 相关需求（MCP 接口平台、Skill 工程、Agent 集成、RAG 知识库）
- **全栈经历**：技术栈/中间件/职责/业绩成果。各段经历相对详细，不写一行概括：
  - 后端框架（Spring 具体组件）、前端框架、数据库、中间件、团队角色、代表性成果
- **城市原因**：为什么在目标地区（成都）工作发展（**"本地人回流定居"是最强稳定性信号**）
- **薪资要求**：按用户当前预期填写

### 3. 结构编排（重要性降序）

个人介绍 → **AI 实践（独立成章，最显眼）** → 工作经历（全栈详细）→ 技术栈（按 AI/后端/前端/数据库/领域归类）→ 基本信息（含城市发展说明）→ 个人评价

### 4. 措辞约束

谦逊务实，避免"领域专家"、"精通"、"主导"，改用"方向"、"熟练"、"参与"。

### 5. 产出文件

简历.md → 简历.html（保留排版样式）→ 简历.pdf（Playwright 打印 HTML，用 generate_pdf.py）

## 输出

`简历.md` / `简历.html` / `简历.pdf`（同一内容，三种格式）。

## 注意事项

- 不知道的信息逐步询问用户完善，不编造
- 简历中**不包含**相关企业内容
- PDF 生成前提醒用户关闭已打开的旧 PDF，避免文件占用；必要时生成版本化文件名（简历_v2.pdf）
