# 求职流程编排（总入口）

该技能是求职方法论的总控，不直接产出内容，负责判断用户处于哪个环节并调用对应子技能。方法论底稿见 `求职历程.md`。

## 流程地图

```
收到 JD / 企业名
      │
      ▼
① 企业独立分析 → qiuzhi-company-analysis（输出 {企业}分析.md）
      │
      ▼
② 简历编写 → qiuzhi-resume（输出 简历.md/html/pdf）
      │
      ▼
③ 面试准备 → qiuzhi-interview-prep（输出 面试细节.md 专项章节）
      │
      ▼
④ 面试执行+复盘 → qiuzhi-interview-review（更新 面试细节.md + {企业}分析.md）
      │
      ▼
⑤ 多 offer 对比 → qiuzhi-offer-compare（输出 企业对比.md）
      │
      ▼
⑥ 薪资谈判 → qiuzhi-negotiation（更新 企业对比.md）
      │
      ▼
最终决策（用"定义问题 vs 执行者"标准终审）
```

## 路由判断

| 用户消息 | 触发子技能 |
|----------|-----------|
| 给我分析这家公司 / 这个 JD 怎么样 | ① qiuzhi-company-analysis |
| 帮我写简历 / 更新简历素材 | ② qiuzhi-resume |
| 这个岗位怎么面试 / 准备面试清单 | ③ qiuzhi-interview-prep |
| 刚面完试，复盘一下 / 这轮怎么样 | ④ qiuzhi-interview-review |
| 几个 offer 怎么选 / 要不要放弃 XX | ⑤ qiuzhi-offer-compare |
| 一会儿谈薪资 / 薪资怎么谈 | ⑥ qiuzhi-negotiation |

多环节同时出现时（如"分析公司 + 准备面试"），先按文档依赖顺序逐个执行，每完成一个环节输出一份文档。

## 核心原则

1. **结论先行**：每份文档开头一句话给结论，再展开论证
2. **一企一档 + 全局一表**：单家企业独立分析管"这家值不值得"，全局对比管"几家怎么选"
3. **面试情报及时回流**：面试得到的信息（真实岗位画像、薪资、加班、团队构成）当天更新文档
4. **确定性 > 想象**：已落袋的 offer 是底盘，未到手的按"有戏但不是救命稻草"对待

## 文档体系速查

| 文档 | 作用 | 何时更新 |
|------|------|----------|
| 求职历程.md | 方法论（本体系底稿） | 新增方法论时 |
| 职业方向.md | 职业定位与转型目标 | 方向变化时 |
| 工作经验.md | 工作经历素材 | 素材补充时 |
| 个人特长.md | 能力/特长素材 | 素材补充时 |
| 相关企业.md | 企业登记/排除/分类 | 每接触一家企业 |
| {企业}分析.md | 单家企业深度分析 | 面试情报回流时 |
| 企业对比.md | 多 offer 对比与决策 | 每次对比/谈判后 |
| 面试细节.md | 面试准备 + 复盘 | 每次面试前后 |
| 简历.md / html / pdf | 最终交付物 | 简历调整时 |

## 候选人的硬约束（执行所有子技能时必须遵守）

- 排除外包企业
- 所有推荐企业必须有目标城市（成都）办公点
- 简历措辞谦逊，不用"精通/主导/领域专家"，用"方向/熟练/参与"
- 简历突出 AI 实践（vibe coding、MCP/Skill、AI 解决问题），AI 实践独立成章
